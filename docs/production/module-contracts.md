# Module Production Contracts

This document captures the minimum production contract for each module. Detailed behavior stays in domain/app tests and API docs; this file records the baseline invariants implementers must preserve.

| Module | Inputs | Outputs | Invariants | Errors | Idempotency | Retry behavior | Security requirements |
|---|---|---|---|---|---|---|---|
| identity | Auth credentials, OAuth callbacks, MFA codes, workspace/member commands | Sessions, users, workspaces, memberships, auth emails, identity events | Workspace boundaries are explicit; sessions bind to one user; tokens expire and can be revoked | Typed auth, token, MFA, invitation, and workspace errors | Refresh/logout/revoke are safe to repeat; token-consuming flows are one-time | Email sends may retry outside user transactions; auth checks do not retry invalid credentials | Never log passwords, tokens, recovery codes, or raw OAuth secrets; enforce workspace access |
| access | Actor context, API key bearer tokens, role/scope mutation commands | Permission decisions, API key metadata, role assignments, audit/events | Raw API key material is returned once only; stored keys are hashed; scopes are workspace-bound | Typed invalid key, denied scope, invalid permission, conflict errors | Key revocation and permission assignment are safe to repeat when state already matches | Authentication failures are not retried; transient repository failures may be retried by caller | Never expose key hashes or full key values; audit key lifecycle changes |
| sender | Workspace sender-domain commands, DNS verification requests | Sender readiness, DNS records/status, sender events | Only verified/active senders are production-send eligible; domains are workspace-scoped | Not found, invalid domain, verification failed, access denied | Verification refresh can be repeated and converges on current DNS state | DNS lookups must use bounded timeout; transient DNS failures may be retried | Prevent cross-workspace verification/use; do not log customer DNS secrets if added later |
| audience | Contact/list/segment CRUD, import/export job commands | Contacts, lists, segments, job states, audience events | Email identity is normalized per workspace; archived contacts are not eligible unless explicitly restored | Validation, conflict, not found, access denied, storage unavailable | Import/export job creation should use stable job IDs or idempotency when exposed to clients | Worker retries must not duplicate contacts or artifacts | Enforce workspace access and consent/suppression integration |
| content | Template CRUD, publish, render/preview requests | Template versions, render output, snapshots, content events | Published versions are immutable; rendering is deterministic for the same version/input | Template invalid, render invalid, not found, version conflict | Publish should not create duplicate current versions for the same request | Rendering failures are terminal for bad payloads and retryable for infra failures | Do not execute untrusted template code; enforce workspace access |
| campaign | Campaign lifecycle commands, schedule/cancel/pause/resume | Campaign state, candidates, delivery handoff events | Lifecycle transitions are explicit; scheduling cannot enqueue duplicate batches | Invalid transition, schedule invalid, dependency not ready, access denied | Schedule/cancel/pause/resume should be safe under client retry | Worker retries must preserve logical single enqueue per campaign/recipient | Recheck access and dependencies at mutation boundaries |
| delivery | Transactional send requests, due-message worker jobs, provider results | Messages, attempts, retry state, delivery events | Provider calls occur outside DB transactions; message/attempt state machines are monotonic | Validation, suppressed, sender/template invalid, provider temp/permanent failure | Transactional send uses idempotency key; duplicate worker delivery is logically single-send | Retry only temporary failures with bounded backoff; terminal provider failures stop retries | API key auth required for transactional APIs; never log recipient tokens or provider credentials |
| ingestion | Provider webhook payloads and headers | Raw provider events, normalized events, ingestion events | Provider event IDs/fingerprints dedupe repeated webhooks; normalization preserves source traceability | Signature invalid, malformed payload, unsupported event, duplicate event | Duplicate provider events are accepted as no-op after dedupe | Webhook handler returns fast; heavy processing is retried by workers | Verify provider signatures where supported; limit request size |
| tracking | Tracking IDs, click IDs, unsubscribe tokens | Pixel/redirect/unsubscribe responses, tracking events, suppression writes | Public endpoints never require auth; unsubscribe is idempotent; redirects only to stored safe targets | Invalid/expired token, unknown tracking ID, unsafe redirect, malformed request | Opens/clicks may dedupe by tracking ID and event fingerprint; unsubscribe repeat is success/no-op | Transient event writes may retry without changing user-visible unsubscribe result | Do not log full URLs with tokens or raw recipient personal data |
| suppression | Suppress/unsuppress commands, unsubscribe/complaint/bounce inputs | Suppression entries, decisions, suppression events | A suppressed recipient is not eligible for send in the matching scope | Duplicate entry, not found, invalid scope/reason, access denied | Suppress/unsuppress are safe to repeat to the same target state | Retried complaint/bounce handling must not create duplicate active entries | Enforce workspace isolation; avoid raw email logging |
| analytics | Email facts, projection updates, report queries, sync cursor requests | Postgres projections, ClickHouse reports, freshness metadata | Postgres facts are canonical; ClickHouse-backed reads disclose freshness/unavailable state | Invalid query, unavailable ClickHouse, not found, access denied | Fact ingestion dedupes by event identity | Sync retries must not duplicate logical facts or skip cursor advancement incorrectly | Enforce workspace access on every report |
| webhooks | Customer webhook config commands, delivery jobs, replay requests | Webhook configs, delivery attempts, signed outbound requests, events | Target URLs must be safe; deliveries include event identity and signature | Invalid target URL, secret conflict, delivery temporary/permanent failure, access denied | Delivery jobs dedupe by event/config identity where possible | Retry temporary network/5xx failures with bounded backoff and terminal state | Defend against SSRF; never expose webhook secrets after creation/rotation |
| notification | Notification commands and eligible domain events | Notification messages, attempts, provider sends, events | Notifications are generated only for allowed product events | Invalid recipient/template, provider failure, disabled provider | Message creation should dedupe by source event | Retry temporary provider failures with bounded backoff | Do not include secrets or sensitive raw personal data in messages/logs |
| audit | Sensitive action records, search queries | Append-only audit entries and search results | Audit entries are immutable after write; payload summaries are minimal | Validation, access denied, storage failure | Recording may dedupe by source event where available | Audit writes inside sensitive workflows should fail closed where required by policy | Redact secrets and raw tokens; workspace access required for reads |
| operations | Outbox/DLQ/replay queries and commands | Operational summaries, DLQ records, replay jobs, events | Replay is explicit, permission-checked, audited, and observable | Invalid replay request, not found, access denied, conflict | Replay job creation should avoid duplicate active jobs for same target set | Replay workers retry safely and preserve original event identity | Operations endpoints require authenticated user access and appropriate permissions |
| platform | Env config, migration files, infra clients, health checks | Config objects, client pools, metrics, health/readiness, OpenAPI | Unsafe production config is rejected; shutdown honors context; migrations are ordered | Config validation, connection, migration, health dependency errors | Startup and health checks are repeatable | Infra clients use bounded connect/check timeouts and caller-controlled retry | Redact secrets in config/log/error paths |
